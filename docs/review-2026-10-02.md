# Code review — outstanding issues

A top-to-bottom review of the repository (2026-10-02, at `78b4424`), kept up
to date as findings are fixed: this lists only what is still open
(last updated 2026-10-03). Locations name the file and function rather than
line numbers, which drift.

Each finding was traced through the code; those marked *reproduced* were also
run. Backwards compatibility with earlier versions' files and clients isn't a
goal for now, so nothing here is about it.

## Done: protocol seams (2026-10-03)

What each protocol does is out of `Engine` and `Trunk`, so a new protocol is
a module of its own plus a line where decoders are made
(`docs/architecture.md` § Adding a protocol):

- `VoiceDecoder` for voice channels (chosen per call: a P25 system has Phase 1
  and Phase 2 voice, SmartNet analog and P25);
- `ControlChannel` for a system's control channel(s);
- enums for the data that crosses into config and status.

| Step | What | State |
|---|---|---|
| 1 | `VoiceDecoder` trait and its four implementations (`trunk/voice.rs`), used by trunked calls | done: identical on every capture |
| 2 | Conventional channels use the same decoders (its `Rx` goes) | done: identical on every capture |
| 3 | `ControlChannel` trait: P25, SmartNet and DMR out of `Trunk`, with a carrier plan (one hunted control channel, or every carrier) | done: identical on every capture |
| 4 | `Protocol` / `ProtocolStatus` enums in place of `smartnet` / `dmr` options | done: identical on every capture |
| 5 | Site lock compares the fields each protocol states (`trunk/identity.rs`: `Identity` is a set of `IdField`s, not P25 options); Setup shows only those fields | done: identical on every capture, and with a matching, a mismatching and a System ID lock |
| 6 | Saving a call (`drop_short`, the minimum length, normalising, levels, the call JSON) out of `Engine`: `record::save_call` | done: identical on every capture |

**How each step is checked.** Reference captures, replayed before and after
with the same command; the outputs must be byte-identical. The captures and
scripts are in `captures/` (not in git; see its README). Each capture is 90 s at
2.4 MSPS from free dongles (2026-10-03):
- DCFD P25 on two radios: 3 calls, 3,575 control messages;
- WMATA SmartNet on two radios: 24 calls (4 analog, 20 digital);
- the Capacity Plus and Capacity Max DMR sites: control channels only, no
  calls during the capture;
- conventional DMR, and conventional P25 / FM, from the same captures;
- DCFD with its 770 MHz Phase 2 channels (added afterwards): 5 calls on both
  slots, also identical to the code before the refactor.

Every call's WAV, JSON and vocoder frames, every decoded control message and
the log are compared.

## Architecture

The overall shape is sound:

- `trunk-core` does no I/O.
- `trunk-app` (`Session`) is the single platform-independent façade.
- The desktop and browser builds are thin shells around `Session`.
- One protocol (`protocol.ts`) is shared by both transports and checked
  against Rust in a test.
- Plugins are separate processes behind a lossy queue.
- All control-channel decoders converge on one `trunk::Message`.
- A system's identity is its short name, unique across every system; numbers
  are handles for one run (`docs/architecture.md` § Identifiers).

Where it will strain as it grows:

- **`Engine`** (`trunk/engine.rs`, about 1,440 lines) is now call routing and
  the radio. Done 2026-10-03, identical on every capture:
  - Talker aliases are an `AliasBook` (`units.rs`).
  - Multi-site linking and choosing the copy to keep are in `multisite.rs`
    (`MultiSite::link_new`, `conclude`).
  - What voice channels hear reaches the calls at one point per block:
    after the source's voice and control channels, at the block's time.
    Applying it before the control channels was tried. Audio came out
    identical, but 14 calls' `stop_time` moved one block (5 ms) early.
  - Better still, later: note each frame at its own air time (`VoiceOut.t`)
    rather than the block's.
- **The clock** (done 2026-10-03). Each live source's sample clock is
  measured against the wall clock (`Session`'s `ClockFit`):
  - it is set at once on the first samples (a radio's open time);
  - it is then slewed toward each 10 s window's measure (crystal error).
  - Replays are unchanged (identical on every capture). A test shows a radio
    whose samples start 3 s late gets its calls at the right wall time.
  - Left: a busy engine makes samples look late. The window's minimum
    absorbs short spells, but one that stays behind for minutes would pull
    the clock late too, by up to the length of its queue.
- **The interface has no login.** With `--bind 0.0.0.0` anyone who can reach
  it can change settings and install or run plugins, and `config` messages
  carry plugin API keys. Remote management (e.g. over Tailscale) is expected,
  so refusing remote browsers isn't the answer; an optional token would fit.

The schema test (`protocol_tests.rs`) is good but has blind spots:

- `status` is only exercised with a conventional-only config, so
  `SystemStatus`, `identity`, `adjacent`, `patches` and `dmr` are never
  shape-checked.
- Optional fields TS declares but Rust never sends can't be caught (how
  `siteGroup` went missing).
- Several messages are checked by name only: `unitAlias`, `plugin*`,
  `error`, `notice`.
- Field names the server *reads* from commands aren't checked.

## Naming

- **Config keys.**
  - Unit suffixes are inconsistent. Some keys carry them (`centerHz`,
    `gainDb`, `prerollS`, `bitrateKbps`). Others carry units without one
    (`controlChannels`, `voiceChannels`, `channels`, `lcnTable`,
    `bandplanBase`, `ppm`, `controlWarnRate`), and some of those also accept
    MHz.
  - The discriminator is `kind` on sources but `type` on systems.
  - DMR keeps Trunk Recorder's names (`lcnTable`, `channels`) while
    everything else is renamed.
  - `talkgroupsCsv` and `unitNames.csv` hold text, while `channelFile` holds
    a path.
  - Airspy `gain` / `lnaGain` / … are driver steps, while Soapy `gains` are
    dB.
- **Framers.** There are four `Framer` types (`p25::frame`, `p25::phase2`,
  `dmr::burst`, `smartnet::osw`), with outputs `Frame` / `Packet` / `Burst` /
  `FramerOut`. Some take options (`new(opts)`), others use `Default`.
- **Burst sizes.** `BURST_DIBITS` is 170 in phase2 and 132 in dmr. The
  matching whole-slot constant is `SLOT_DIBITS` in one and `UNIT_DIBITS` in
  the other.
- **Slot.** "slot" is superframe slot 0–11 in `Packet.slot` but TDMA slot
  0 / 1 elsewhere.
- **Rates.** `SYMBOL_RATE` is defined three times, while C4FM / MSD
  hard-code 4800. Rates are called `fs`, `rate`, `rate_hz` and
  `output_rate`.
- **Soft bits and error counts.** Each protocol has its own soft-bit
  convention (parallel `Vec` with −1, signed `soft()`, `Bit.soft`) and its
  own error-count type (`i32` with −1, `u32` tuples, `u8`).
- **Engine types.**
  - `recorder_num` is a pool slot for trunked calls but the channel index for
    conventional ones.
  - `start_recording` / `stop_recording` also start and stop *following* an
    encrypted call.
  - `conv_calls: Vec<CallManager>` only allocates ids.
- **Duplicated helpers.**
  - RRC taps (3×).
  - Windowed-sinc low-pass (2×).
  - CRC-CCITT (2×).
  - Bit-field readers (2×).
  - DMR depends on `p25::phase2` for the AMBE+2 codeword FEC; that belongs in
    a shared module.
