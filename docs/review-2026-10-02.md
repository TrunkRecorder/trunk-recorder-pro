# Code review — outstanding issues

A top-to-bottom review of the repository (2026-10-02, at `78b4424`), kept up
to date as findings are fixed: this lists only what is still open
(last updated 2026-10-03). Locations name the file and function rather than
line numbers, which drift.

Backwards compatibility with earlier versions' files and clients isn't a
goal for now, so nothing here is about it.

## Pending

- **Existing config files** (the desktop config, WMATA's) use the old key
  names (`kind`, `controlChannels`, Airspy `gain`, …) and must be converted
  to those in `docs/configuration.md` before the app will read them.

## Architecture

- **The interface has no login.** With `--bind 0.0.0.0` anyone who can reach
  it can change settings and install or run plugins, and `config` messages
  carry plugin API keys. Remote management (e.g. over Tailscale) is expected,
  so refusing remote browsers isn't the answer; an optional token would fit.
- **Voice timing.** What voice channels hear reaches the calls at the
  block's time. Noting each frame at its own air time (`VoiceOut.t`) would
  be more exact.

## Bugs

| Sev | Where | What |
|---|---|---|
| low | `dsp/c4fm.rs` (levels) | After a gap of *exact* silence longer than the peak window (a synthetic capture; real gaps carry noise), the gap's symbols aren't "quiet" and enter the level history. In small pushes this can mis-slice the next burst's first ~250 symbols until the history refreshes. The levels could ignore symbols far below the last known burst level |

## Tests

The schema test (`protocol_tests.rs`) has blind spots:

- `status` is only exercised with a conventional-only config, so
  `SystemStatus`, `identity`, `adjacent`, `patches` and `dmr` are never
  shape-checked.
- Optional fields TS declares but Rust never sends can't be caught.
- Several messages are checked by name only: `unitAlias`, `plugin*`,
  `error`, `notice`.
- Field names the server *reads* from commands aren't checked.

## Naming

- `trunk-pro/src/snrtool.rs` keeps its own low-pass. The shared one
  (`dsp/filters.rs`) differs by an f32 ulp in about 1 % of tap sets (a
  different operation order); it's a tool-only path.
- Setup's SmartNet band-plan select doesn't offer the aliases
  (`800_rebanded`, …); configs using them still work.
