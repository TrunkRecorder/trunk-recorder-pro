# P25 systems

This page explains how Trunk Recorder Pro records a trunked P25 system: what to enter in Setup,
how it follows calls on Phase 1 and Phase 2 voice channels, which modulation to pick, how it
learns the band plan, and what it does with encrypted and unit-to-unit calls. Every key is listed
in the [trunked systems reference](../configuration/systems.md).

## What it handles

A P25 trunked system has a **control channel**: one frequency that transmits all the time,
announcing which talkgroup is talking on which voice channel (a *grant*), plus housekeeping such
as the system's identity and its band plan. The recorder listens to the control channel and, for
each grant, opens the voice channel and records the call.

Trunk Recorder Pro handles:

- **Phase 1** voice channels (FDMA, IMBE vocoder), whether the site transmits C4FM or CQPSK
  (the "LSM" modulation simulcast systems use).
- **Phase 2** voice channels (TDMA, two calls per frequency, AMBE+2 vocoder). The control
  channel is still Phase 1; the grant says which slot a call is on.
- Multi-site systems, one site per system entry. See [Several systems and sites](multi-site.md).
- Motorola and Harris talker aliases. See [Talkgroups and units](talkgroups-and-units.md#talker-aliases).

SmartNet systems with P25 voice channels are a different system type: see [SmartNet](smartnet.md).
Conventional (non-trunked) P25 channels are covered in [Conventional channels](conventional.md).

## Setting it up

The easiest way in is **Find my system** in Setup, which scans for a control channel, reads the
system's identity, band plan and neighbours, measures your radio's frequency error and fills the
system card in for you. See [Find my system](find-my-system.md).

To add one by hand, go to **Setup** → **Systems**, click **Add a system**, and fill in:

- **Short name**: the folder its calls go into, and the name its learned band plan and talker
  aliases are kept under. Each system needs its own.
- **Type**: **P25**.
- **Modulation**: see [Modulation](#modulation-auto-c4fm-or-cqpsk) below. **Auto (both
  receivers)** is the safe choice.
- **Control channels, MHz**: the control channel first, then the alternates from RadioReference.
  "Later ones are fallbacks": if the recorder hears nothing good on the current one for 5 seconds,
  it moves to the next in the list.
- **Talkgroups**: a talkgroup CSV, or a paste from RadioReference. See
  [Talkgroups and units](talkgroups-and-units.md).

In the config file the same system looks like this (frequencies are in Hz):

```json
{
  "shortName": "dcfd",
  "type": "p25",
  "controlChannelsHz": [857987500, 858987500],
  "modulation": "qpsk",
  "talkgroupsName": "dcfd.csv",
  "talkgroupsCsv": "Decimal,Hex,Alpha Tag,Mode,Description,Tag,Category\n101,65,FD Disp,D,Fire Dispatch,Fire Dispatch,Fire\n"
}
```

The talkgroup file is kept inside the config, as text, rather than as a path to a file.

Every control channel and voice channel has to fall inside one of your sources' bands (less the
guard band at the edges). The system card in Setup shows a chip for this: **control channel on
source 1**, or **no control channel inside a source**; after a survey it also shows how many of
the voice channels it heard are covered. See [Radios](radios.md) for placing sources.

## How calls are followed

1. The control channel sends a grant: talkgroup, source radio, and a *channel number*.
2. The recorder turns the channel number into a frequency using the band plan (below). Phase 2
   channel numbers also give the slot.
3. If the talkgroup should be recorded (see [Encryption](#encrypted-calls) and
   [Talkgroups and units](talkgroups-and-units.md)), it opens that voice channel on whichever
   source covers it, starting a second before the grant (the pre-roll) so the first syllable isn't
   lost.
4. The control channel keeps sending updates while the call goes on. The call ends when neither
   the control channel has mentioned it nor any audio has arrived for the **Call timeout** (3
   seconds by default).

If no source covers a voice channel, the call isn't recorded and the **Radio system** page counts
it as **Out of band**. If every recorder is busy (32 by default), it counts as **No recorder**.

### Phase 2

A Phase 2 voice channel carries two calls at once, one in each TDMA slot. The recorder opens the
frequency once and decodes both slots; each call is saved on its own, with `.0` or `.1` at the end
of the file name and `tdma_slot` and `phase2_tdma` in the call JSON.

Phase 2 voice is scrambled with a pattern worked out from the site's NAC, System ID and WACN.
There is nothing to configure: the recorder takes all three from the control channel's broadcasts.
Until it has heard all three (normally within the first few seconds after it starts), it can't
descramble Phase 2 voice.

## Modulation: Auto, C4FM or CQPSK

P25 Phase 1 is sent one of two ways:

- **C4FM** (`fsk4`): the usual modulation of a single-transmitter site.
- **CQPSK** (`qpsk`), also called LSM: used by **simulcast** systems, where several transmitters
  send the same signal on the same frequency at once so that one channel covers a large area.
  Where you hear two or more of those transmitters, their signals arrive a little apart in time
  and smear into each other. A C4FM receiver copes badly with that; a CQPSK receiver with an
  equaliser copes much better.

| Setting | Key value | What runs on each control and voice channel |
|---|---|---|
| **Auto (both receivers)** | `auto` (default) | a CQPSK receiver, a CQPSK receiver with an equaliser, and a C4FM receiver; each frame is taken from whichever decoded it best |
| **C4FM (fsk4)** | `fsk4` | the C4FM receiver only |
| **CQPSK / LSM simulcast (qpsk)** | `qpsk` | the two CQPSK receivers only |

Auto works for either kind of system and costs the most CPU. Once you know what your system
sends, picking it saves CPU, which matters on a Raspberry Pi or with many calls at once. The
**Decode** page's badge shows what the control channel actually is (for example **P25 · CQPSK**),
judged by which receivers decode the most frames. If you know the site is simulcast, `qpsk` is the
right choice.

This setting doesn't affect Phase 2 voice channels, which always use their own receiver.

## Band plans (IDEN)

A grant names a channel number, not a frequency. The control channel regularly broadcasts the
system's channel tables (*IDEN* messages: base frequency, channel spacing, and whether a table is
Phase 1 or Phase 2), and the recorder learns them from the air. You never type a P25 band plan.

A grant heard before the matching IDEN can't be followed, and the recorder skips it. To avoid
that gap on every start, the tables are saved to `<shortName>.bandplan` in the folder the config
file is in, and loaded on the next start. The file is rewritten when the system broadcasts
something different. If you rename a system, the old file isn't used; the new name learns the
tables again from the air in a few seconds.

## Site lock

A site lock keeps a system on the right control channel, which matters when a neighbouring site
or another system is close in frequency. It is under **Site lock** at the bottom of the system
card: **NAC**, **WACN**, **System ID** (all in hex), **RFSS** and **Site** (decimal). Leave a field
empty to accept anything. Find my system fills it in.

A control channel that announces a different identity isn't followed: its grants are ignored, the
recorder moves on to the next control channel in the list, and the log and dashboard say why
("The control channel is another system's: NAC 2A3 (expected 293)"). Grants also wait until every
locked field has been heard, which takes a few seconds after starting.

In the config file these values are plain JSON numbers, in decimal: NAC 443 hex is `"nac": 1091`.
See [Several systems and sites](multi-site.md#site-lock) for more, and for adding the neighbouring
sites a control channel announces.

## Encrypted calls

The recorder can't decrypt anything. What it does with encryption:

- A grant flagged encrypted, or a talkgroup whose **Mode** in the talkgroup file is `E`, `DE` or
  `TE`, isn't recorded. It is still *followed*: its voice channel is opened to read who is talking
  and their talker alias, which are sent in the clear. The **Radio system** page counts these as
  **Encrypted**.
- A call that turns out to be encrypted partway through (the voice frames say so) has those
  transmissions left out of its audio.
- With `recordEncrypted` set to `true`, encrypted calls are recorded and kept, with no audio for
  the encrypted parts. This is in the config file only (globally under `recording`, or in a
  system's `recording`); there is no switch for it in Setup.

`De` and `Te` (encrypted only sometimes, in RadioReference's notation) are recorded, as in Trunk
Recorder.

## Unit-to-unit calls

A private call between two radios is granted like a group call, with the receiving radio's ID in
place of a talkgroup. These are recorded by default, filed under the receiving radio's ID as if it
were a talkgroup. Turn them off with **Unit-to-unit calls** under **Call rules** on the
**Recording** tab (`recordUnitToUnit`), or per system in its **Recording override**.

## What the dashboard shows

On the **Decode** page each P25 system has a card with:

- **Control messages** per second, against what is usual for it, and the current control channel
  frequency (or "hunting").
- **Control lost**: the share of control messages that failed to decode. A few percent is normal.
- **Phase error** (CQPSK) or **Eye opening** (C4FM): how clean the demodulated signal is. The
  hints give the scale: phase error under 10° is clean, 20° or more marginal; eye opening 10 or more
  is clean, under 4 means errors. A simulcast site reads low on eye opening.
- **Framing**: frames with a failed header or missed sync, and equaliser resets per minute.
- **Voice lost**: the share of voice frames that couldn't be used over the last 10 minutes. Under
  2% is clean.

Click a system for its detail: NAC, WACN, System ID and site, the channels open now, a table of
every frequency it used over 24 hours or 7 days (calls, SNR, offset, clean and lost frames, by
hour), **Neighbouring sites** the control channel announces that you aren't recording yet (each
with an **Add** button), and **Patches** standing now.

## Diagnostic tools

For digging into a problem, record the raw signal and decode it offline. `trunk-pro capture`
records an RTL-SDR to a file (unsigned 8-bit IQ, as `rtl_sdr` writes):

```bash
trunk-pro capture dcfd.cu8 --freq 858500000 --rate 2400000 --seconds 60
```

Then:

| Command | What it shows |
|---|---|
| `trunk-pro tool cc dcfd.cu8 --center 858500000 --rate 2400000 --cc 857987500` | every control channel block (TSBK) decoded, as JSON lines (time, NAC, opcode, hex) |
| `trunk-pro tool voice dcfd.cu8 --center … --rate … --freq 859037500 [--audio out.f32]` | one Phase 1 voice channel, frame by frame; `--audio` writes the voice as raw 8 kHz float samples |
| `trunk-pro tool p2 cap.cu8 --center … --rate … --freq Hz --nac N --sysid N --wacn N [--slot 0\|1] [--audio out.f32]` | one Phase 2 channel's slots; NAC, System ID and WACN in decimal or with `0x` for hex |
| `trunk-pro replay dcfd.cu8 --center … --rate … --cc 857987500 --out calls` | the whole recorder on the capture, writing calls like a live run |
| `trunk-pro survey dcfd.cu8 --center … --rate …` | what Find my system makes of the capture |

`tool cc` and `tool voice` take `--demod cqpsk|c4fm|auto` to try one receiver at a time, which is a
quick way to see which modulation suits your site. Every flag is listed in
[Command line](../command-line.md).

## Common problems

**"No control channel of … falls inside any source's bandwidth".** Move a source's center
frequency, set it to Auto, or add a source. See [Radios](radios.md).

**"Not decoding its control channel — hunting for another".** Nothing is decoding on the
frequency. Check the frequency, the antenna and the gain, and that the source's ppm correction is
right (or AutoTune is on). Try each control channel from RadioReference: only one is usually on the
air.

**Lots of control messages lost, choppy or garbled voice, on a simulcast system.** Set the
modulation to `qpsk`, and try moving the antenna: simulcast reception often changes a lot over a
few metres. The **Decode** page's frequency table shows whether it's every channel or only some.

**The control channel is another system's.** The site lock doesn't match what the control
channel announces. If you typed the lock into the config file by hand, check that the NAC, WACN
and System ID are in decimal there, not hex.

**Calls are missed for the first few seconds after the first start.** The band plan hasn't been
heard yet. From the second start on, the saved `.bandplan` file covers it.

**Talkgroups are skipped as Encrypted.** They are encrypted, or the talkgroup file marks them `E`,
`DE` or `TE`. See [Encrypted calls](#encrypted-calls).

**Calls show as Out of band.** The voice channel isn't inside any source. The **Decode** page's
frequency table and the system card's **voice … covered** chip show which ones; widen or move a
source, or add one.
